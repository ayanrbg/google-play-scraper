# PlayTrend — поиск идей для игр в Google Play

[playtrend.lol](https://playtrend.lol) каждый день сканирует Google Play и находит молодые игры, которые быстро набирают установки,
а также поисковые запросы со спросом и слабой конкуренцией. Бренды и паблишеры, растущие на закупке
трафика, помечаются и скрываются фильтрами. Сделан как SaaS: команды, приглашения, тарифы.

## Как устроено

```
backend/                Python 3.12, FastAPI, SQLAlchemy, Alembic
  playtrend/play/       клиент Google Play: чарты, автодополнение, карточки, поиск, страницы
  playtrend/pipeline/   ежедневный конвейер: charts → expand → enrich → track → metrics → keywords
  playtrend/api/        REST API для сайта
  migrations/           миграции схемы БД
frontend/               React + Vite + TypeScript (сайт), Caddy (HTTPS + раздача)
deploy/                 docker-compose для сервера: Postgres, API, воркер, Caddy, бэкапы
legacy/                 старая версия (Streamlit + SQLite в git), только для истории
```

### Откуда данные

| Источник | Что даёт | Как часто |
|---|---|---|
| Топ-чарты (Top Free, **Top New Free**, **Movers & Shakers**, Top Grossing) × 18 игровых категорий × 37 стран | новые игры и где они растут | раз в день |
| Карточка игры | установки (общие на весь мир), дата релиза, оценки, монетизация | раз в день для игр моложе года |
| Похожие игры у лучших кандидатов | «снежный ком» вокруг хита | раз в неделю на игру |
| Страницы разработчиков | признак бренда (другие хиты студии) и новые релизы студий | раз в 30 дней |
| Коллекция предрегистраций Google | игры до релиза | раз в день |
| Автодополнение поиска + выдача | спрос и конкуренция по запросам | порциями каждый день |

### Алгоритм

- **Задержка данных Google.** Счётчик установок обновляется ступеньками раз в 1–3 дня. Скорость
  считаем между реальными точками обновления, а не «вчера–сегодня». Скачки распределяем по дням.
  На графиках пунктир означает, что Google ещё не обновил счётчик: это не падение до нуля.
- **Trend Score (0–100)** складывается из пяти частей:
  - скорость за 7 дней — до 40;
  - ускорение неделя к неделе — до 15;
  - свежесть релиза — до 15;
  - охват чартов по странам — до 20;
  - рейтинг — до 10.
- **Бренд-фильтр.** Флаги каждой игры:
  - крупный издатель, паблишер гиперказуала, франшиза — по редактируемым спискам;
  - «студия 50M+» и «40+ игр» — считаются автоматически.

  Каждый флаг включается и выключается в фильтрах. По умолчанию скрыты первые три.
- **Ниши в поиске.**
  - Спрос: насколько коротким префиксом Google подсказывает запрос.
  - Конкуренция: медиана установок топ-10, доля брендов, точные совпадения в названиях.
  - Возможность: выше, если в топ-10 уже пробились молодые игры.
- **Аналитика игры** (страница игры):
  - «Как нашли»: первое появление в каждом канале — чарт (страна, место), «Похожие» у какой игры,
    страница студии, пре-регистрации, поиск по запросу — плюс обновления и скачки установок.
  - «Почему растёт»: оценка драйверов по данным — поиск (позиции × спрос), чарты, трафик извне стора
    (рост без видимости в сторе, скачки без причины), признаки закупки (паблишер, софт-лонч, мало оценок
    на 1000 установок относительно жанра), эффект обновлений, волна похожих игр. Google источники
    трафика не раскрывает, поэтому это оценка, а не факт.
  - «Ключи игры» (обратный ASO, по кнопке): во всех языковых рынках берём название и описания,
    находим фразы и подсказки Google, меряем спрос и позицию игры в поиске. Собирает воркер
    (~300–700 запросов на игру, 3–10 минут), сайт только ставит в очередь. Кнопка доступна всем, включая гостей:
    пересборка не чаще раза в сутки, очередь до 20 игр, с одного IP — 5 запусков в час.
    Вручную: `python -m playtrend.cli keys <app_id>`.

**Зрелость данных.** Скорость за неделю становится надёжной примерно через 8 дней после запуска.
Ускорение — примерно через 15. Поэтому сбор важно запустить как можно раньше.

## Сервер

**Рекомендация: Hetzner Cloud CX23** — 2 vCPU, 4 ГБ RAM, 40 ГБ SSD, €5,49 в месяц (цена с июня 2026).
Если его нет в наличии — OVHcloud VPS-1.

- Нагрузка сетевая, а не вычислительная. Узкое место — лимит Google на один IP, около 2 запросов
  в секунду. Мощный сервер это не ускорит, поэтому брать дороже нет смысла.
- Память: около 1,2 ГБ в покое, до 2 ГБ на пиках. Диск: база растёт на 2–4 ГБ в год,
  всего с системой, Docker и бэкапами за первый год уйдёт около 15–20 ГБ.
- Скачивание: 6–10 ГБ в день входящего трафика. Входящий трафик провайдеры обычно не тарифицируют.
- Ориентировочная длительность прогонов:
  - первый полный прогон — 3–5 часов: нужно один раз скачать карточки ~20–30 тыс. игр из чартов;
  - дальше ежедневный конвейер — 1,5–3 часа.
- Подойдут и аналоги: DigitalOcean, Vultr, Timeweb Cloud — от 2 ГБ RAM, Ubuntu 22/24.

Что теряем на бесплатных вариантах:

- **GitHub Actions.** Нет постоянной базы и сайта, лимит 6 часов на запуск. Старая версия сломалась
  именно на этом: база в git упёрлась в лимит 100 МБ.
- **Oracle Cloud Free Tier.** Бесплатно и мощно, но регистрацию часто отклоняют, а простаивающие
  машины могут забрать.
- **Свой компьютер.** Работает (тот же docker compose), но должен быть включён круглосуточно.
  Удобен как временный вариант, пока нет сервера: базу потом можно перенести через `pg_dump`.

## Запуск на сервере

1. Купите сервер (Ubuntu) и домен. В DNS домена сделайте A-запись на IP сервера.
2. Установите Docker на сервере:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. Скопируйте проект и заполните настройки:
   ```bash
   git clone https://github.com/ayanrbg/google-play-scraper.git && cd google-play-scraper/deploy
   cp .env.example .env
   nano .env   # DOMAIN, пароли (openssl rand -hex 24), email и пароль первого админа
   ```
4. Запустите:
   ```bash
   docker compose up -d --build
   ```
   Caddy сам получит HTTPS-сертификат. Сайт откроется на `https://ваш-домен`.
5. Войдите под админом. Первый сбор стартует в `PLAYTREND_DAILY_HOUR_UTC`. Чтобы не ждать, нажмите
   «Запустить сейчас» на странице «Данные».
6. Пригласите команду: «Настройки → Команда → Создать ссылку».

Обслуживание:

```bash
docker compose logs -f worker                  # что делает сбор
git pull && docker compose up -d --build       # обновление (миграции применятся сами)
ls backups/                                    # ежедневные дампы базы, хранятся 7 дней
```

## Локальная разработка

```bash
python -m venv .venv && .venv/Scripts/pip install -r backend/requirements.txt pytest httpx
cd backend
../.venv/Scripts/python -m playtrend.cli migrate                  # SQLite в data/playtrend.db
../.venv/Scripts/python -m playtrend.cli create-user me@x.io pass1234 --superadmin
../.venv/Scripts/python -m uvicorn playtrend.api.main:app --port 8000
../.venv/Scripts/python -m pytest                           # тесты
cd ../frontend && npm install && npm run dev                # http://localhost:5173
```

Отдельные этапы конвейера: `python -m playtrend.cli run charts enrich track metrics`.
Импорт истории из старой базы (май–июнь 2026): `python -m playtrend.cli import-legacy ../data/monitor.db`.

## SaaS

- Сайт открыт: без аккаунта видно всё (радар, карточки, ниши, жанры, студии, CSV, «Данные»).
  Гости ничего не меняют, но могут заказать сбор ключей игры (его выполняет воркер). Лимит запросов с одного IP (`backend/playtrend/api/ratelimit.py`) бережёт
  сервер и не даёт подбирать пароли. Сайт только читает базу: в Google (и через прокси) ходит
  один воркер (по расписанию и по очереди ключей), это проверяет тест `test_api_never_loads_the_scraping_network_layer`.
- Данные рынка общие. Отметки, заметки и сохранённые фильтры принадлежат команде (workspace)
  и видны только после входа.
- Регистрация настраивается переменной `PLAYTREND_REGISTRATION`:
  - `invite` — только по приглашениям (сейчас);
  - `open` — открытая регистрация.
- Тарифы и лимиты (строки, история, ниши, экспорт, места) описаны в `backend/playtrend/plans.py`.
  Тариф команды меняется в «Настройки → Платформа». Оплату (Paddle, LemonSqueezy, ЮKassa)
  подключим позже: она будет просто менять тариф.
- Тексты интерфейса вынесены в `frontend/src/format.ts`, чтобы потом добавить английский.
